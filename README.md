# 🧱 Цеглинка — інтернет-магазин конструкторів LEGO®

Повноцінний інтернет-магазин для українського ринку: каталог з фільтрами, кошик для гостей і
зареєстрованих покупців, оформлення замовлення без реєстрації, оплата через **LiqPay** або
накладеним платежем, доставка **Новою Поштою** (відділення, поштомат, кур'єр), **Укрпоштою** та
самовивіз, особистий кабінет і адмін-панель. Інтерфейс українською, ціни в гривнях.

> «Цеглинка» — вигадана назва з власним логотипом. Магазин не пов'язаний з групою компаній LEGO.
> Усі зображення товарів — локальні SVG-заглушки, згенеровані скриптом.

## Можливості

| Розділ | Що реалізовано |
|---|---|
| **Головна** | Банер, переваги, серії (категорії), популярні товари, новинки |
| **Каталог** | Сітка товарів; фільтри: серія, вік, ціна, кількість деталей, наявність; сортування: популярність, новизна, ціна; пошук за назвою та артикулом; пагінація; зрозумілі URL `/catalog/technic` |
| **Товар** | Галерея, артикул, ціна і стара ціна зі знижкою, наявність, деталі, вік, опис, «Додати в кошик», схожі товари, Schema.org `Product` |
| **Кошик** | Зміна кількості, видалення, підсумок, прогрес до безкоштовної доставки. Гостьовий кошик зберігається за httpOnly-cookie, кошик користувача — у БД; після входу/реєстрації вони об'єднуються |
| **Оформлення** | 4 кроки: контакти → доставка → оплата → перевірка. Без реєстрації. Вартість доставки перераховується в реальному часі |
| **Кабінет** | Профіль, зміна пароля, історія замовлень зі статусами, збережені адреси |
| **Службові** | Вхід, реєстрація, відновлення пароля, успішна оплата, помилка оплати, 404 |
| **Адмінка** `/admin` | Дашборд (замовлення, виручка, товари, що закінчуються), товари (пошук, CRUD, завантаження зображень, швидка зміна ціни і залишку), категорії, замовлення (фільтри за статусом і датою, зміна статусу, ТТН), користувачі, налаштування доставки |
| **Оплата** | LiqPay (картки будь-яких банків, Apple Pay, Google Pay), підписаний запит, webhook з перевіркою підпису та суми; накладений платіж |
| **Доставка** | Нова Пошта через офіційний API (міста, відділення, поштомати, кур'єр, розрахунок вартості за вагою та оголошеною вартістю), Укрпошта (фіксований тариф), самовивіз; безкоштовна доставка від суми; резервні тарифи без ключа API |
| **SEO** | Метатеги, Open Graph, canonical, `sitemap.xml`, `robots.txt`, JSON-LD (Product, BreadcrumbList, Store) |

## Стек

- **Next.js 16** (App Router, Server Components, Server Actions) + **TypeScript**
- **Tailwind CSS 4**
- **PostgreSQL 16** + **Prisma ORM 6**
- **Auth.js (NextAuth v5)** — email + пароль (bcrypt), ролі `USER` / `ADMIN`, JWT-сесії
- **Zod** — валідація всіх вхідних даних на сервері
- **Vitest** — тести
- **Docker Compose** — база для розробки; production-стек з **Caddy** (автоматичний HTTPS)

## Найпростіший запуск (без Docker)

Потрібен лише **Node.js 22** (https://nodejs.org, кнопка LTS).

1. Завантажте проєкт: на GitHub **Code → Download ZIP** і розпакуйте (або `git clone`).
2. Запустіть подвійним кліком:
   - **Windows:** `start-windows.bat`
   - **Mac:** `start-mac.command` (якщо macOS не дає відкрити — правий клік → «Відкрити»)
   - **Linux:** `./start-mac.command` або `npm install && npm run local`

Скрипт сам встановить залежності, створить `.env` з випадковим секретом, запустить вбудований
PostgreSQL у папці `.local-db` (порт 54329, Docker не потрібен), застосує міграції, заповнить каталог
тестовими товарами (лише при першому запуску) і відкриє сайт у браузері. Перший запуск триває кілька
хвилин, наступні — секунди. Дані зберігаються між запусками.

Адмінка: `/admin`, вхід `admin@example.com` / `Admin12345!` (змінюється в `.env`). Зупинка — `Ctrl+C`
у вікні терміналу. Щоб почати з чистої бази, видаліть папку `.local-db` і файл `.local-db.seeded`.

## Локальний запуск

Потрібно: **Node.js ≥ 20.9** (рекомендовано 22), **Docker** (або власний PostgreSQL 14+).

```bash
# 1. Залежності
npm install

# 2. Змінні середовища
cp .env.example .env
#   відредагуйте .env: обов'язково AUTH_SECRET і ADMIN_PASSWORD
#   AUTH_SECRET згенеруйте так: openssl rand -base64 32

# 3. База даних
docker compose up -d          # PostgreSQL на localhost:5432 (shop/shop)

# 4. Міграції та тестові дані
npx prisma migrate deploy
npm run db:seed

# 5. Запуск
npm run dev                   # http://localhost:3000
```

Адмін-панель: http://localhost:3000/admin — вхід з `ADMIN_EMAIL` / `ADMIN_PASSWORD` з `.env`.

Без ключів LiqPay і Нової Пошти сайт повністю працює: доступна оплата при отриманні, а доставка
Новою Поштою рахується за резервними тарифами (місто й відділення вводяться вручну). Без SMTP
листи (відновлення пароля, підтвердження замовлення) виводяться в консоль сервера.

## Наповнення бази (seed)

`npm run db:seed` створює:

- 6 серій: City, Technic, Friends, Creator 3-в-1, DUPLO, Classic;
- 26 товарів з різними цінами, знижками, залишками (є «закінчуються», «немає в наявності» та один прихований);
- налаштування доставки зі значень `.env`;
- адміністратора з `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME`.

Скрипт ідемпотентний: повторний запуск оновлює записи (за артикулом/slug/email), а не дублює їх.
Повторний запуск також оновлює пароль адміністратора — так його можна скинути.

## Ключі LiqPay

1. Зареєструйтеся на [liqpay.ua](https://www.liqpay.ua/) (потрібен рахунок ФОП/юрособи в ПриватБанку
   або іншому банку-партнері) і створіть магазин.
2. У кабінеті: **Налаштування магазину → API** — скопіюйте **публічний** і **приватний** ключі.
   Для тестування є sandbox-ключі (починаються з `sandbox_`).
3. Додайте в `.env`:
   ```env
   LIQPAY_PUBLIC_KEY="sandbox_i0000000000"
   LIQPAY_PRIVATE_KEY="sandbox_xxxxxxxxxxxxxxxx"
   LIQPAY_SANDBOX=1      # 0 — лише для реальних платежів
   ```
4. `NEXT_PUBLIC_SITE_URL` має бути публічною адресою сайту: LiqPay надсилає callback на
   `https://ваш-домен/api/payments/liqpay/callback` і повертає покупця на `/payment/return`.

**Тестування callback локально.** LiqPay не може достукатися до `localhost`, тож скористайтеся тунелем
(наприклад, `cloudflared tunnel --url http://localhost:3000` або `ngrok http 3000`) і вкажіть отриману
адресу в `NEXT_PUBLIC_SITE_URL`. Навіть без callback сторінка повернення сама запитує статус платежу в
LiqPay (підписаним запитом `action=status`).

Як це працює:
- платіж формується **на сервері**: `data = base64(JSON)`, `signature = base64(sha1(private + data + private))`;
- покупця перенаправляють на `https://www.liqpay.ua/api/3/checkout`;
- webhook **спершу перевіряє підпис** (порівняння за сталий час), потім `public_key`, суму і валюту — і лише
  тоді позначає замовлення оплаченим; повторні callback нічого не змінюють;
- приватний ключ ніколи не потрапляє в браузер.

## Ключ API Нової Пошти

1. Увійдіть в [особистий кабінет Нової Пошти](https://new.novaposhta.ua/) (бізнес-акаунт).
2. **Налаштування → Безпека → API-ключі → Створити ключ**.
3. Додайте в `.env`:
   ```env
   NOVA_POSHTA_API_KEY="ваш-ключ"
   NOVA_POSHTA_SENDER_CITY_REF="8d5a980d-391c-11dd-90d9-001a92567626"   # Ref міста відправника (Київ)
   ```
   Ref іншого міста можна отримати методом `Address.getCities` (див. [документацію API](https://developers.novaposhta.ua/)).

З ключем на сторінці оформлення з'являється пошук міст і список відділень/поштоматів, а вартість
рахується методом `InternetDocument.getDocumentPrice` за вагою кошика та оголошеною вартістю. Якщо ключа
немає або API не відповідає (тайм-аут 6 с) — використовуються резервні тарифи з адмінки
(**Налаштування**), і сайт продовжує працювати.

Тариф Укрпошти, резервні тарифи НП і поріг безкоштовної доставки змінюються в **/admin/settings**
(початкові значення — з `.env`).

## Розгортання на Vercel

SSL видається автоматично, редирект http→https і HSTS вмикаються платформою та застосунком.

1. **База даних.** Створіть PostgreSQL (Vercel Marketplace → Neon / Supabase / Prisma Postgres або
   будь-який зовнішній). Скопіюйте рядок підключення.
2. **Сховище зображень.** Vercel → Storage → **Blob** → Create — змінна `BLOB_READ_WRITE_TOKEN`
   додасться автоматично (файлова система Vercel лише для читання).
3. Імпортуйте репозиторій у Vercel. Скрипт `vercel-build` (`prisma generate && prisma migrate deploy && next build`)
   застосує міграції під час кожного деплою.
4. **Environment Variables** (Production): `DATABASE_URL`, `AUTH_SECRET`, `NEXT_PUBLIC_SITE_URL=https://ваш-домен`,
   `LIQPAY_*`, `NOVA_POSHTA_*`, `SMTP_*`, `MAIL_FROM`, `PICKUP_ADDRESS`, значення доставки.
   `AUTH_TRUST_HOST` на Vercel не потрібен.
5. Після першого деплою заповніть базу з локальної машини:
   ```bash
   DATABASE_URL="postgresql://...prod..." ADMIN_EMAIL=... ADMIN_PASSWORD=... npm run db:seed
   ```
6. Підключіть свій домен у **Settings → Domains** — сертифікат видасться автоматично.

## Розгортання на VPS (Docker + Caddy)

Caddy автоматично отримує й оновлює сертифікат **Let's Encrypt**, перенаправляє http→https і додає HSTS.

1. Сервер з Docker і Docker Compose (Ubuntu 22.04+, ≥ 1 ГБ RAM; для збірки краще 2 ГБ або swap).
2. DNS: A-запис (і AAAA, якщо є IPv6) домену → IP сервера. Відкрийте порти **80** і **443**.
3. Склонуйте репозиторій і налаштуйте `.env`:
   ```bash
   cp .env.example .env
   nano .env
   ```
   Обов'язково: `DOMAIN`, `ACME_EMAIL`, `POSTGRES_USER`, `POSTGRES_PASSWORD` (складний!), `POSTGRES_DB`,
   `AUTH_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`. `DATABASE_URL` і `NEXT_PUBLIC_SITE_URL` для контейнерів
   задаються в `docker-compose.prod.yml` автоматично.
4. Запуск:
   ```bash
   docker compose -f docker-compose.prod.yml up -d --build
   ```
   Контейнер `migrate` застосує міграції, після чого стартує `app`, а `caddy` отримає сертифікат.
5. Тестові дані та адміністратор:
   ```bash
   docker compose -f docker-compose.prod.yml run --rm migrate npx prisma db seed
   ```
6. Оновлення: `git pull && docker compose -f docker-compose.prod.yml up -d --build`.
7. Резервні копії:
   ```bash
   docker compose -f docker-compose.prod.yml exec db pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > backup.sql
   ```
   Завантажені зображення зберігаються у volume `uploads`.

База даних не відкрита назовні; застосунок доступний лише через Caddy.

## Безпека

- **Паролі** — bcrypt (cost 12). Однаковий час відповіді для неіснуючих користувачів.
- **Обмеження спроб**: вхід — 5 невдалих спроб на пару IP+email і 30 на IP за 15 хв; реєстрація — 5/год з IP;
  відновлення пароля — 3/год на email; оформлення — 10 замовлень/10 хв з IP. Лічильники в PostgreSQL —
  працюють і на кількох інстансах/serverless.
- **Відновлення пароля** — одноразовий токен на 1 год, у БД лише його SHA-256; відповідь не розкриває,
  чи існує акаунт.
- **Валідація** — усі Server Actions і API-маршрути перевіряють дані через Zod; ціни та вартість доставки
  завжди перераховуються на сервері.
- **Права доступу** — `proxy.ts` відсікає неавторизованих, а **кожна** адмінська сторінка і дія викликає
  `requireAdmin()`, що читає роль з БД (позбавлення прав діє миттєво).
- **Замовлення гостей** відкриваються лише за секретним токеном у посиланні (порівняння за сталий час).
- **HTTPS** — Vercel/Caddy (редирект + сертифікат), `FORCE_HTTPS=1` для інших проксі.
- **Заголовки** — `Strict-Transport-Security`, `Content-Security-Policy`, `X-Frame-Options: DENY`,
  `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`.
- **Cookie** — сесія Auth.js і кошик: `HttpOnly`, `SameSite=Lax`, `Secure` у production (`__Secure-` префікс на HTTPS).
- **Завантаження файлів** — тип визначається за сигнатурою (JPG/PNG/WEBP/AVIF), SVG заборонено, ≤ 5 МБ,
  випадкові імена, віддача з `nosniff`.
- **Захист від open redirect** — після входу дозволені лише внутрішні адреси.
- **Секрети** — лише у змінних середовища (`.env` у `.gitignore`).

## Як додати Monobank або WayForPay

Платіжний код винесено в `src/lib/payments`:

```ts
// src/lib/payments/types.ts
interface PaymentProvider {
  id: string;                                         // "monobank"
  title: string;
  isConfigured(): boolean;
  createPayment(order: PaymentOrder): PaymentRedirect; // URL сторінки оплати
  parseCallback(body): PaymentCallback;               // перевірка підпису + нормалізований статус
  checkStatus?(externalId): Promise<PaymentCallback | null>;
}
```

1. Створіть `src/lib/payments/monobank.ts`, що реалізує інтерфейс (для Monobank `createPayment` стане
   асинхронним — створення інвойсу через API; підпис webhook перевіряється ECDSA-ключем).
2. Зареєструйте провайдера в `src/lib/payments/index.ts`.
3. Webhook автоматично доступний за адресою `/api/payments/monobank/callback`; логіка оновлення
   замовлення (`applyPaymentResult`) спільна для всіх провайдерів.

## Обмеження та нотатки

- Товари резервуються в момент створення замовлення (і для онлайн-оплати теж). Неоплачені замовлення
  адміністратор скасовує вручну — залишки повертаються на склад автоматично.
- CSP дозволяє `'unsafe-inline'` для скриптів: Next.js вбудовує інлайн-скрипти гідратації, а nonce-CSP
  зробив би всі сторінки повністю динамічними. Зовнішні скрипти не завантажуються.
- Поштомати Нової Пошти рахуються за тарифом «відділення–відділення».
- `PICKUP_ADDRESS` та контакти магазину (`src/config/site.ts`) замініть на реальні.
