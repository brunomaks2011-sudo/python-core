# BRICK HUB — интернет-магазин LEGO для Украины

Полноценный магазин оригинальной продукции LEGO: наборы, **отдельные детали по номеру и цвету** (как на BrickLink) и минифигурки. Интерфейс на украинском, цены в гривнах (₴).

Стек: **Python 3.13 · Django 5.2 LTS · SQLite или PostgreSQL**. Страницы рендерятся на сервере (быстро и хорошо для SEO), JavaScript используется только для удобства: подсказки поиска, мини-корзина, автодополнение Новой почты. Без него всё работает.

## Что умеет

**Витрина**
- Главная: баннер «Набори, деталі й мініфігурки LEGO» на серой пластине с шипами и тремя товарами в наличии, у которых есть своё фото (сначала отмеченные «Популярний (головна)»; пока таких нет — кирпичик, минифигурка и пластина), кнопки «До каталогу» и «Знайти деталь», серии LEGO (с логотипом, если он загружен), новинки, популярные товары, поиск деталей, рідкісні та колекційні набори, минифигурки, «Рекомендуємо» (хиты продаж), категории деталей, преимущества, недавно просмотренные.
- Каталог: наборы по сериям (City, Technic, Star Wars, Icons, Creator, Speed Champions, Harry Potter, NINJAGO, Marvel, Minecraft, Friends, Architecture, Ideas, Super Mario, другие); детали по 31 категории (цеглинки, скоси, арки, пластини, базові пластини, плитки, панелі, колеса, деталі для транспорту, вікна/двері, крила, шарніри, шестерні, Technic, електроніка, прозорі, рослини, тварини, частини мініфігурок, волосся та головні убори, частини мініляльок, аксесуари для фігурок, зброя, огорожі, контейнери, трубки, прапори, наліпки, DUPLO, Bionicle, інші) и ещё 54 подкатегориям третьего уровня по типам деталей каталога (например, «Частини мініфігурок → Голови / Торси / Ноги», «Волосся та головні убори → Волосся / Шоломи / Капелюхи», «Елементи Technic → Балки / Осі / Штифти…»); минифигурки по сериям; брелоки; книги с фигурками; аксессуары по 12 разделам (зберігання, вітрини, освітлення, сепаратори, канцелярія, сумки, одяг, годинники, магніти, ігри та пазли, декор, інші); подборки «Новинки», «Розпродаж», «Набори б/у», «Рідкісні».
- Поиск по названию (укр./англ.), номеру набора, Design ID, Element ID, номеру минифигурки (каталожному или BrickLink sw0001), цвету («3001 червоний», «3023 black») и серии. Подсказки появляются прямо при вводе.
- Фильтры: цена, тип, категория, серия, цвет (палитра), состояние, наличие, год, количество деталей. Сортировка по популярности, новизне, цене, названию и рейтингу.
- Карточка товара: галерея со стрелками, номера с кнопкой копирования, выбор цвета детали (список и квадратики цветов, у каждого цвета своё фото, цена и остаток), переключатель «Новий / Б/у», цена, наличие, количество, корзина, избранное, сравнение, характеристики (детали, минифигурки, год, возраст, размеры), комплектация минифигурки, отзывы и рейтинг, похожие и недавно просмотренные товары, «Повідомити про надходження».
- Страница детали `/detali/3001/` — таблица всех цветов: номер цвета BrickLink, Element ID, состояние, остаток, цена за штуку. Можно сразу положить в корзину несколько цветов.
- **Заказ деталей списком**: вставляете строки вида `3001 5 10` или `3023 Black 24`, и всё, что есть в наличии, попадает в корзину.
- Справочник цветов LEGO с номерами BrickLink и Rebrickable.

**Корзина и заказ**
- Корзина в базе данных: у гостя по сессии, у покупателя в аккаунте; при входе они объединяются. Купить больше, чем есть на складе, нельзя: счётчик количества на странице товара, в таблице цветов детали и в корзине останавливается на остатке (кнопка «+» становится бледной и при нажатии объясняет почему), сервер тоже не кладёт в корзину больше остатка.
- Промокоды: процент или фиксированная сумма, минимальная сумма заказа, только на наборы/детали/минифигурки, лимит использований, срок действия, один раз на покупателя.
- Оформление: имя, фамилия, телефон (проверяется украинский формат), e-mail, город, отделение или почтомат Новой почты, курьер, Укрпошта с индексом, способ оплаты, комментарий, создание аккаунта.
- При заказе товар списывается со склада внутри транзакции, поэтому одну и ту же последнюю штуку не продадут двоим. Каждое движение по складу записывается в журнал.
- Письма покупателю (заказ принят, смена статуса) и менеджеру (новый заказ).

**Личный кабинет**: регистрация, вход по e-mail, восстановление пароля, личные данные и адрес доставки, история заказов, статус-таймлайн и ТТН со ссылкой отслеживания, «Повторить заказ», отмена, избранное, подписки на поступление. Отследить заказ можно и без аккаунта — по номеру и телефону.

**Админ-панель `/panel/`** (только для сотрудников)
- Статистика: выручка за день, 7 и 30 дней, средний чек, график по дням, заказы по статусам, топ товаров, заканчивающиеся товары, стоимость склада.
- Товары: типы «Набір», «Деталь», «Мініфігурка», «Брелок», «Книга з фігуркою», «Аксесуар»; у брелока и книги можно указать номер LEGO и минифигурку в комплекте (необязательно). Цвет, серия и категория выбираются полем с поиском: начните вводить название по-украински, по-английски или номер цвета (категории выбранного типа товара стоят в списке первыми). Для аксессуара форма не спрашивает о наборе: нет полей «Характеристики набору», номер LEGO необязателен. Поиск, фильтры, правка цены и остатка прямо в таблице, массовые действия (в том числе «Перенести в категорію…» и «Кількість на сайті: показувати / не показувати»; галочка «Усі знайдені за фільтром» применяет действие ко всем товарам фильтра на всех страницах, удалять так нельзя — только отмеченные), добавление и редактирование с **автозаполнением из каталога по номеру LEGO**, загрузка нескольких фото (уменьшаются, превью WebP), место на складе, журнал движения.
- **Чий товар.** У каждого товара есть владелец — владелец магазина или партнёр, который продаёт свои товары через магазин. Новый товар принадлежит тому, кто его добавил; в списке товаров владелец виден цветной меткой, есть фильтр и массовое действие «Позначити, чий товар…». Позиция заказа запоминает владельца в момент продажи. В статистике — таблица «Продажі за власниками товарів» (сегодня, 7 и 30 дней, всего, штук, товаров и стоимость склада), в заказе — сумма по каждому владельцу. Скидка по промокоду делится между владельцами пропорционально их товарам, к которым она применилась; доставка не учитывается.
- **Фото без фона.** У загруженного фото однотонный фон (бумага, стол, стена, лайтбокс) убирается автоматически, тень становится мягкой полупрозрачной, предмет обрезается с небольшим полем. Фото с фоном сохраняется: у каждого фото в карточке товара есть «Повернути фон» / «Прибрати фон» и пометка, что с ним сделано. Пёстрый фон или предмет во весь кадр не трогаются (с пояснением). Старые фото обрабатывает кнопка «Прибрати фон зі старих фото» в списке товаров или команда `python manage.py remove_photo_backgrounds`. Отключить: `SHOP_REMOVE_PHOTO_BACKGROUND=0`.
- Заказы: смена статусов с письмом покупателю. Отмена и возврат автоматически возвращают товар на склад. Ввод ТТН переводит заказ в «Відправлене». Есть пакувальний лист, отсортированный по месту на складе.
- Пользователи (блокировка, права сотрудника), промокоды, отзывы (модерация), подписки на поступление.
- Справочники: категории, серии, цвета, каталог деталей, Element ID, каталог наборов и минифигурок.
- **Массовый импорт CSV / Excel (.xlsx)** на тысячи строк: детали, наборы, минифигурки, обновление остатков и цен по артикулу. Сначала режим «Перевірити без збереження» с отчётом по строкам, потом запись. Номера сверяются с официальным каталогом. Есть шаблоны .xlsx и экспорт всех товаров в CSV.
- Системная админка Django `/django-admin/` для суперпользователя.

## Дизайн

Витрина яркая, в цветах кубиков LEGO: много белого, а цвет — сплошными блоками, как в собранной модели. Все стили — в `static/css/app.css`, цвета и размеры заданы переменными в начале файла (`:root`). Предыдущий, чёрно-белый вариант сохранён в истории git (коммит `759788c`).

- **Палитра.** Цвета кубиков: жёлтый `#FFCF00` (баннер главной, кнопки «Додати в кошик» и корзина в шапке, метка «Новинка»), синий `#0A63C9` (главные кнопки, ссылки, выбранные фильтры, полоска над шапкой, блок «Деталі за номером», метка «Рідкісний»), красный `#D6101A` (логотип, «Розпродаж», скидка, сердце избранного, счётчики), зелёный `#12813A` («Є в наявності», кнопка после добавления в кошик, доставленные заказы), оранжевый `#F28C0F` (метка «Хіт»), бирюзовый `#36AEBF` и тёмно-синий `#0E2A47` (подвал). «Закінчується» — тёмно-оранжевый `#B9560B`. Текст и линии нейтральные: `#111111`, `#383838`, `#6E6E6E`, `#E8E8E8`, фон фото — `#F5F5F5`. Белый текст стоит только на синем, красном, зелёном и тёмно-синем, чёрный — на жёлтом, оранжевом и бирюзовом, везде с контрастом не ниже 4,5 : 1.
- **Главная.** Баннер — жёлтая пластина с шипами и товарами магазина на ней. Серии LEGO — цветные «кубики» с двумя шипами в углу (шесть цветов по кругу); первыми идут серии, где больше всего товаров, показывается не больше 14 (две строки на компьютере). Кроме основных серий (галочка «Показувати в меню наборів») туда попадают и другие серии магазина — DC, Jurassic World, Disney и т. д., — как только в них появляется товар. Плитки с персонажами (картинки владельца в `static/img/series/`): DC — `#3B3D4C` с Бэтменом, BrickHeadz — `#3B3D4C` с Эмметом (серия BrickHeadz тоже попадает на главную, как только в ней есть товар), Star Wars — `#141414` с Дартом Вейдером, NINJAGO — красная с Каем, Harry Potter — бордовая `#7A1F2B` с Гарри на метле. City — синяя `#12318B` с полицейским. Collectible Minifigures — светло-серая `#E4E6EA` с фанатом в костюме динозавра. Disney — тёмно-синяя `#15375A` с Микки Маусом. Marvel — тёмно-зелёная `#0D3B26` с Доктором Думом. На плитках всегда пишется название серии; загруженный логотип серии показывается на странице товара. Перед каждым заголовком раздела — шип своего цвета. «Деталі за номером» — синяя пластина с жёлтой кнопкой «Знайти». Иконки «Лише оригінал», «Деталі поштучно», «Доставка», «Оплата», «Допомога» — в цветных квадратиках.
- **Шрифт.** Manrope для всего текста; заголовки 700, заголовок баннера 800, цены и номера — моноширинные цифры (`tabular-nums`). Логотип — прежний: красный знак с шипами и надпись BRICK HUB шрифтом Unbounded, «HUB» красным, на компьютере под ним «Набори · деталі · мініфігурки».
- **Кнопки.** Главная — синяя с белым текстом, «Додати в кошик» — жёлтая с чёрным текстом (после добавления на мгновение становится зелёной с галочкой), второстепенная — светло-серая, «в обране» — круглая светло-серая, выбранное — красное сердце, недоступная кнопка — серая.
- **Карточка товара** как на lego.com. Скидка — красная метка «−19%» рядом с зачёркнутой старой ценой, новая цена красная (на телефоне у старой цены не пишется «₴», чтобы метка помещалась рядом даже на экране 360 px); на странице товара метка стоит рядом с ценой. У наборов иконка торта с возрастом («10+») и иконка детальки с количеством деталей, у минифигурок — деталька с числом частей. Возраст берётся из поля «Вік від, років» в карточке товара в панели (или колонки `age` при импорте): пока поле пустое, торта нет. На телефоне возраст и детали стоят отдельной строкой над номером набора, чтобы соседние карточки были на одном уровне.
- **Шип LEGO** — фирменная деталь: знак логотипа (четыре шипа), пластины с шипами (жёлтая в баннере, синяя у поиска деталей), шипы на «кубиках» серий и перед заголовками, точка наличия (зелёная — есть, оранжевое кольцо — заканчивается, серая — нет).
- **Анимация** на CSS и немного JS, без библиотек. На главной при открытии баннер собирается по очереди (заголовок, текст, кнопки, затем товары на пластине), а каждый следующий блок появляется один раз, когда до него докручивают; страницы каталога не двигаются. Фото в карточке слегка увеличивается под мышью, сердце «подпрыгивает» при добавлении в избранное, значок корзины и счётчик отвечают на добавление товара, галочка на кнопке «Додати в кошик» появляется с отскоком. Переходы между страницами плавно перетекают (браузеры с View Transitions). Нажатие слегка уменьшает кнопку, меню открываются за 180 мс, боковые панели — за 320 мс. Эффекты наведения работают только с мышью, а при включённой в системе настройке «уменьшить движение» остаётся только плавное проявление без сдвигов.
- **Телефоны и планшеты.** Отдельная мобильная раскладка: поиск под шапкой, меню и фильтры выезжают сбоку, фото товара во всю ширину, а когда главная кнопка «Додати в кошик» уходит за экран, снизу появляется панель с ценой и кнопкой. На планшетах в каталоге 3 колонки, на мониторах от 1600 px страница становится шире, а карточки не уменьшаются.
- Дизайн до этой переработки сохранён в истории git: коммит `feedde3`.

## Быстрый старт

```bash
cd brickhub
```

```bash
python3 -m venv .venv
```

```bash
source .venv/bin/activate
```

Windows: `.venv\Scripts\activate`

```bash
pip install -r requirements.txt
```

```bash
cp .env.example .env
```

```bash
python manage.py setup_store
```

```bash
python manage.py createsuperuser
```

```bash
python manage.py runserver
```

`setup_store` создаёт таблицы, загружает справочный каталог LEGO (≈26 000 наборов, 62 000 деталей, 17 000 минифигурок, 275 цветов) и демо-ассортимент магазина. Без демо-товаров: `python manage.py setup_store --no-demo`.

Откройте http://127.0.0.1:8000/ (магазин) и http://127.0.0.1:8000/panel/ (админка, вход под созданным суперпользователем).

Тесты:

```bash
python manage.py test tests
```

## Откуда данные и что в них настоящее

| Данные | Источник |
| --- | --- |
| Номера наборов, названия, годы, количество деталей и минифигурок | Каталог [Rebrickable](https://rebrickable.com/downloads/) |
| Номера деталей (Design ID), официальные названия, типы | Rebrickable |
| Цвета: названия, HEX, номера Rebrickable | Rebrickable |
| Номера цветов BrickLink (106 цветов) | Сопоставлены по названию с данными BrickLink |
| Комплектация минифигурок, в каких наборах встречаются | Rebrickable |
| Украинские названия деталей, цветов и категорий | Переведены для магазина (официальное английское название показывается рядом) |
| **Цены, остатки, флаги «Новинка/Хит», промокоды WELCOME10 / DETALI15 / MINIFIG100** | **Демо-значения.** Замените их в админке или импортом |

Номера деталей **не выдумываются**: Design ID, номер BrickLink и Element ID вводит владелец. Если номера ещё нет в каталоге (например, торс с принтом `973pb1234c01`), форма товара добавит его сама: название и раздел магазина берутся со страницы каталога BrickLink (сервер делает один запрос и кэширует ответ на 30 дней), а если BrickLink недоступен — раздел берётся от основной детали из каталога (`973` → «Торси»), а название — «Торс (973pb1234c01)». Своё название можно задать в блоке «Свою назву для нового номера». В импорте новые номера добавляются, если отмечена галочка «Додати нові номера в каталог» (не больше 40 запросов к BrickLink за один файл); без неё неизвестный номер попадает в отчёт как ошибка.

**Element ID и все номера.** В репозитории лежат таблицы каталога Rebrickable, только номера и названия, без картинок (`data/rebrickable`, источник и дата в `SOURCE.txt`): 114 789 Element ID с LEGO Design ID, 65 016 деталей, 17 366 минифигурок и 28 605 наборов (включая 2 323 набора, вышедших после основного каталога, в том числе 2026–2027 годов) с сериями. Номер никогда не становится названием: если набора, минифигурки или детали нет ни в каталоге, ни на BrickLink, форма просит вписать название в поле «Назва», и запись каталога создаётся с этим названием. Загрузить их в базу сайта: `python manage.py update_catalog` (несколько секунд). Команда только добавляет то, чего в справочнике ещё нет, и заполняет пустой LEGO Design ID: названия, разделы и номера, которые уже есть или исправлены в панели, не меняются, товары не трогаются (`--dry-run` — только подсчёт, `--dir ПАПКА` — свежие файлы с rebrickable.com/downloads). **Две нумерации: LEGO и BrickLink.** Сайт LEGO (Pick a Brick) и BrickLink нумеруют детали по-разному (LEGO `35382` = BrickLink `3005`, LEGO `3069` = BrickLink `3069b`, у всех торсов с принтом LEGO `76382`). У детали хранятся оба номера: `Part.lego_no` (номер LEGO, `update_catalog` заполняет его по элементам) и номер BrickLink (`bricklink_no`, если отличается от номера каталога). Везде сначала показывается номер LEGO, потом BrickLink: в форме товара, в списке товаров панели, на странице товара, в экспорте CSV (колонки `lego_design_id`, `element_id`, `bricklink_no`). Для деталей с принтом номер каталога (`…pr0001…`) не выдаётся за номер BrickLink (у BrickLink `…pb…`): он считается неизвестным, пока его не впишут. Номер LEGO, общий для многих деталей (`76382`), сам по себе деталь не выбирает — её даёт Element ID. После этого в форме товара в поле Design ID можно вписать номер каталога, номер BrickLink, официальный LEGO Design ID (например `35382` → деталь `3005`) или Element ID; Element ID можно вписать и в его собственное поле: деталь, цвет, название и раздел подставятся сами, а при выборе цвета подставится Element ID этой детали в этом цвете. Для нового номера с принтом (`973pb…`) раздел берётся по деталям с таким же началом номера (`973…` → «Торси»). Полный перезапуск каталога наборами — `python manage.py import_catalog --csv-dir ПАПКА` (он обновляет и названия). После загрузки выполните `python manage.py rebuild_search_index`.

**Номера минифигурок BrickLink (sw0001 и т. п.)** в открытых данных отсутствуют. В демо используются каталожные номера Rebrickable (`fig-000123`), а поле «Номер BrickLink» заполняется в админке. Поиск понимает оба варианта.

**Фото.** Товар без своего фото показывает картинку из каталога BrickLink: деталь — по номеру BrickLink (или Design ID) и цвету BrickLink, набор — по номеру, минифигурка — по номеру BrickLink. Картинку загружает браузер покупателя напрямую с img.bricklink.com, на сервер ничего не скачивается. Если у BrickLink нет картинки, показывается заглушка «Фото незабаром». Своё фото, добавленное в панели, всегда показывается первым. Отключить картинки BrickLink: `SHOP_BRICKLINK_IMAGES=0`. Удалить все добавленные фото: `python manage.py remove_uploaded_photos --yes` (без `--yes` — только подсчёт). Если у BrickLink нет картинки, а у детали есть Element ID, показывается фото элемента с lego.com; картинки Rebrickable не используются. Необязательная команда `python manage.py fill_from_rebrickable --key КЛЮЧ` может сама подобрать номер BrickLink и Element ID для деталей в продаже (берутся только номера, не фото); если номера вводятся вручную, она не нужна. **Страница товара** сделана в стиле lego.com: большая галерея со счётчиком фото и кнопкой «Усі фото» (на телефоне листается свайпом), цветные метки «Новинка» (жёлтая), «Хіт продажів» (оранжевая), «Рідкісний» (синяя), «Б/у» (тёмная), серия со ссылкой и номер `#40859`, крупное название, цена (при скидке — красная, с зачёркнутой старой ценой и красной меткой «−20%»), наличие (зелёное), счётчик количества, жёлтая кнопка «Додати в кошик» и круглая кнопка «в обране». Под кнопкой — логотип серии, возраст и количество деталей. Логотип загружается в панели: «Серії LEGO» → серия → «Логотип серії» (PNG или WebP с прозрачным фоном); у подсерии показывается логотип основной серии, а пока логотипа нет — название серии. Сколько товара на складе, покупатели по умолчанию не видят: в карточке товара в панели поле «Наявність на сайті» — «Є в наявності» или «Закінчується» (то же — массовым действием в списке товаров); при нулевом остатке — «Немає в наявності». Галочка «Показувати кількість на сайті» в карточке товара (или массовое действие «Кількість на сайті: показувати», можно сразу для всех товаров фильтра) показывает количество: «В наявності: 12 шт.» или «Закінчується: 2 шт.» на странице товара, в карточках и в таблице цветов детали; в списке товаров панели такие товары помечены «кількість видно». Подсказки поиска точный остаток не передают. Шрифт сайта — Manrope (бесплатный, OFL, с кириллицей; фирменный шрифт lego.com Cera Pro платный), логотип BRICK HUB — Unbounded.

**Таблица Excel со всеми товарами.** Кнопка «Експорт Excel» в списке товаров или `python manage.py export_products` (файл в папке `exports/`): артикул, название, тип, Design ID (LEGO), Element ID, номер BrickLink, номер набора или фигурки, цвет, состояние, количество, цена, место на складе, категория, серия, владелец; на втором листе итоги. `clear_products` сохраняет такую таблицу перед удалением и ничего не удаляет, если сохранить её не удалось (`--no-export` — без таблицы). В списке товаров панели у каждого товара без своего фото видно, какая картинка показывается на сайте: «фото з BrickLink», «фото з LEGO» или «без фото — додайте». Есть ли картинка, проверяет браузер владельца (сервер BrickLink может не видеть): при открытии списка непроверенные товары проверяются в фоне, ответ запоминается. Фильтр «Без фото — додайте» показывает только товары, у которых на сайте нет никакой картинки; кнопка «Перевірити ще раз» там же проверяет их заново. После изменения номера, цвета или Element ID товар проверяется снова. Страница панели «Перевірка BrickLink» показывает рядом с каждым товаром его картинку BrickLink и отмечает позиции, которых нет на BrickLink; номер BrickLink и Element ID там правятся прямо в строке.

## Импорт CSV / Excel

Админка → «Імпорт CSV / Excel». Шаблоны .xlsx скачиваются там же. Поддерживаются UTF-8 и Windows-1251, разделитель `;` или `,`, десятичная запятая. Названия колонок можно писать по-английски или по-украински («Номер деталі», «Колір», «Кількість», «Ціна»…).

Детали (до 50 000 строк, новые записываются пакетами):

```
design_id;color_id;condition;quantity;price;location
3001;5;new;250;6,00;A-01-03
3023;11;new;1200;2,00;A-02-11
3069b;;used;40;1,50;B-07-01        ← без color_id нужна колонка color (название)
```

- `color_id` — номер цвета BrickLink (5 = Red, 11 = Black, 86 = Light Bluish Gray), `RB4` — номер Rebrickable, либо колонка `color` с названием (Red / Червоний).
- `element_id` сам определяет деталь и цвет.
- Существующий лот (та же деталь + цвет + состояние) обновляется, новый создаётся.

Наборы: `set_number;condition;quantity;price;old_price;completeness;age;...`. Минифигурки: `fig_number;condition;quantity;price`. Остатки и цены: `sku;quantity;price`.

## Интеграции

Каждая интеграция включается, когда в `.env` есть ключ. Без ключа магазин честно работает в ручном режиме и ничего не имитирует.

| Интеграция | Переменные | Без ключа |
| --- | --- | --- |
| Нова пошта: поиск городов и отделений/почтоматов при оформлении, статус ТТН | `NOVA_POSHTA_API_KEY` (кабинет НП → Налаштування → API) | Город и отделение вводятся вручную, ссылка на отслеживание работает |
| LiqPay: оплата картой, Apple Pay, Google Pay | `LIQPAY_PUBLIC_KEY`, `LIQPAY_PRIVATE_KEY`, `LIQPAY_SANDBOX` | Вариант «Оплата карткою» неактивен, доступен наложенный платёж |
| Укрпошта: статус отправления | `UKRPOSHTA_BEARER_TOKEN` | Ссылка на отслеживание |
| Почта (SMTP) | `EMAIL_HOST`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD` | Письма выводятся в консоль сервера |

Ключ Новой почты не попадает в браузер: запросы идут через сервер (`/api/np/...`) с кешированием и ограничением частоты. Заказ становится «Оплачено» только после callback от LiqPay, у которого проверены подпись, сумма и валюта. Адрес callback: `https://ваш-домен/zamovlennia/liqpay/callback/`.

Код интеграций: `orders/shipping/novaposhta.py`, `orders/shipping/ukrposhta.py`, `orders/payments/liqpay.py`. Другой платёжный сервис (Monobank, WayForPay) добавляется ещё одним классом рядом с LiqPay.

## Развёртывание

**Docker:**

```bash
docker compose up --build
```

Поднимутся PostgreSQL и сайт на :8000. Каталог и демо-данные загружаются один раз:

```bash
docker compose exec web python manage.py setup_store
```

```bash
docker compose exec web python manage.py createsuperuser
```

**Render, Railway и похожие PaaS:** есть `Procfile` (`migrate` при релизе, сайт через gunicorn). Задайте переменные из `.env.example`, обязательно `DJANGO_SECRET_KEY`, `DJANGO_DEBUG=0`, `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS`, `DATABASE_URL`. Статика отдаётся через WhiteNoise. Для загружаемых фото подключите постоянный диск (`DJANGO_MEDIA_ROOT`) или S3-хранилище: на многих PaaS файловая система временная.

**VPS:** gunicorn за nginx (nginx отдаёт `/media/`, тогда задайте `DJANGO_SERVE_MEDIA=0`), HTTPS через Let's Encrypt. После проверки HTTPS включите `DJANGO_HSTS_SECONDS=31536000`.

**Фото товаров** (`/media/products/…`) сайт по умолчанию отдаёт сам, даже при `DJANGO_DEBUG=0`, поэтому они видны и без отдельной настройки веб-сервера (например, на PythonAnywhere без строки `/media/` в «Static files»). Если `/media/` раздаёт веб-сервер, это быстрее — тогда можно выключить `DJANGO_SERVE_MEDIA=0`.

Проверка настроек для прода:

```bash
DJANGO_DEBUG=0 python manage.py check --deploy
```

## Безопасность

- Пароли хранятся хешированными (PBKDF2), действуют валидаторы сложности, после 8 неудачных входов вход блокируется на 15 минут.
- CSRF-защита всех форм, POST для всех изменений, Content-Security-Policy без inline-скриптов, `X-Frame-Options: DENY`, безопасные cookie и редирект на HTTPS в проде. HSTS включается переменной `DJANGO_HSTS_SECONDS`.
- Чужие заказы недоступны: страница заказа открывается владельцу, сотруднику или по секретной ссылке из письма.
- Загружаемые фото проверяются Pillow и перекодируются, у импортируемых файлов ограничены размер и количество строк.
- Секреты только в переменных окружения (`.env` в `.gitignore`).

## Структура

```
brickhub/
  config/      настройки, urls, wsgi
  core/        главная, статические страницы, SEO (JSON-LD, sitemap, robots), middleware безопасности
  catalog/     модели каталога и товаров, поиск, фильтры, генератор SVG деталей, импорт каталога, демо-данные
  cart/        корзина, промокоды, заказ списком
  orders/      оформление, статусы, письма, Новая почта / Укрпошта, LiqPay
  accounts/    пользователь (вход по e-mail), кабинет
  panel/       админ-панель, статистика, импорт/экспорт CSV и Excel
  templates/   HTML-шаблоны (украинский интерфейс)
  static/      CSS, JS, шрифты Manrope и Unbounded (логотип), иконки
  data/        справочный каталог (catalog_full.json.gz) и выборка для демо (catalog_seed.json)
  tools/       скрипт сборки data/ из базы Rebrickable
  tests/       автотесты
```
